# 楚河棋局（增强版）

中国象棋对弈网页游戏：支持**人机对战**（选边 + 四档难度）与**双人联机**（私房对弈）。人机模式可完全离线运行。

技术栈：Vue 3 + TypeScript + Vite + Web Worker + Vitest；联机服务端为 Node.js + WebSocket（ws）。

## 快速开始

```bash
# 安装依赖
npm install

# 启动联机服务端（联机对弈需要，默认 ws://localhost:8787，可用 PORT 环境变量覆盖）
npm run server

# 开发模式（另开终端，默认 http://localhost:5173）
npm run dev

# 运行单元测试（棋规 17 + AI 搜索 8 + 联机房间 10，共 35 例）
npm test

# 生产构建（vue-tsc 类型检查 + 输出 dist/）
npm run build

# 本地预览构建产物（默认 http://localhost:4173）
npm run preview
```

## 玩法

### 人机对弈（离线可用）

- 封面选择「人机对弈」，可先选执色（执红 / 执黑 / 随机，默认执红）与难度（默认普通），点击「开始对弈」。
- 红方始终先走；玩家执黑时，棋盘就绪后电脑自动执红走第一步。执黑时棋盘自动翻转，己方棋子显示在下方、文字保持正向。
- 点击己方棋子显示合法落点（绿色圆点），点击落点完成走子；落子动画、最后一步标记（起点淡色、终点外圈）均按显示方向对齐。
- 顶部显示当前回合、思考状态与胜负结果（按玩家实际执色显示「你赢了 / 电脑赢了」）。
- 「重新开始」沿用本局选边与难度；随机选边则重新抽签。换边视为新局。

四档难度：

| 档位 | 策略 | 最大搜索深度 | 思考预算 |
|---|---|---|---|
| 入门 | 随机合法走法 | — | 立即应招 |
| 普通 | 迭代加深 + Alpha-Beta | 3 | 800ms |
| 困难 | 迭代加深 + Alpha-Beta | 4 | 2500ms |
| 专家 | 迭代加深 + Alpha-Beta | 5 | 12000ms |

搜索引擎（`src/ai/search.ts`）在 Negamax + Alpha-Beta 基础上实现了迭代加深、走法排序（吃子 MVV-LVA / 上一轮最佳 / 杀手 / 历史启发式）、时间检查与静态搜索（quiescence），评估含子力、兵种位置分（车炮马 PST）与残局将帅活跃度。超时采用上一轮完整搜索的最佳走法，Worker 异常时使用经过校验的合法走法兜底。各档实测数据见下方「各档实测结果」。

### 联机对弈（两人私房）

- 封面选择「联机对弈」，可**创建房间**（选执红 / 执黑 / 随机，由服务端分配座位）或**输入 6 位房间码加入**。
- 房主把顶部显示的「房间码」发给对手，对手输入后即可入座；支持等待对手、回合与胜负状态提示。
- 服务端维护权威棋局：校验房间身份、执色、回合、坐标与走法合法性，确认后才广播给双方更新棋盘；棋局状态带递增版本号，重复消息幂等处理。
- 断线自动重连：掉线后顶部显示「对手已断线，等待重连…」；刷新页面会凭本机保存的会话（房间码 + 座位凭证）自动恢复座位。
- 仅房主可「重新开始」（双方同步重置）；「离开房间」释放座位并返回封面。
- 服务端房间保存在内存中，**服务重启即清空所有房间**；双方都掉线超过 10 分钟的房间也会被清理。
- 人机模式不依赖服务端，断网仍可游玩。

## 联机协议与服务端

- 服务端：`npm run server`（`server/index.ts` + `server/game.ts`，可独立测试）。
- 客户端：`src/online.ts` 封装 WebSocket 连接、创建/加入、走子、重开、断线退避重连与会话恢复；WebSocket 地址默认为 `ws://<当前主机>:8787`，可用环境变量 `VITE_WS_URL` 覆盖（构建时生效）。
- 联机冒烟测试（需先启动服务端）：`npx vite-node scripts/online-smoke.ts`，覆盖创建/加入/回合校验/非法走法/重复消息幂等/断线通知/凭证重连/重开/离开共 15 项。

## 规则范围

已实现并覆盖以下棋规（有 Vitest 用例验证）：

- 各棋子走法：帅/将（九宫一步）、仕/士（九宫斜一步）、相/象（田字且塞象眼、不能过河）、马（日字且蹩马腿）、车（直线）、炮（隔一子吃子）、兵/卒（过河前只能前进，过河后可横走、不能后退）。
- 九宫限制、象眼、马腿、过河限制、炮架。
- 将帅照面：两将同列且中间无子视为被将军，撤开挡子造成照面属于自陷将军（非法）。
- 自陷将军过滤：所有走法均不得使己方将军处于被将军状态。
- 被将军时仅允许解将的走法（吃子、垫子、应将）。
- 将死与困毙：轮到的一方无合法走法即判负。

**首版范围之外**：长将（长照）与长捉（重复将军/捉子导致循环）的禁止与判和规则不在本版实现，后续版本再补充。

## 各档实测结果

基准脚本 `npx vite-node scripts/bench.ts` 在四个固定局面下对三档搜索引擎实测（Node，含静态搜索与走法排序）：

| 局面 | 档位 | 走法表现 | 实际用时 | 完成深度 | 搜索节点 |
|---|---|---|---|---|---|
| 开局（初始局面） | 普通 | 兵(6,4)→(5,4)，评 62 | 317ms | 3 | 44,943 |
| 开局（初始局面） | 困难 | 对称局面评分 0，多走法同分 | 1,139ms | 4 | 280,327 |
| 开局（初始局面） | 专家 | 炮(7,7)→(7,2) 中炮经典开局，评 64 | 10,292ms | 5 | 1,879,507 |
| 中局（可白吃车） | 全部 | 全部命中吃车 | 16–27ms | 2 | 约 1–2k |
| 一步杀 | 全部 | 全部命中将死 | 16–27ms | 2 | 约 1–2k |
| 两步杀 | 全部 | 全部命中两步杀 | 16–27ms | 3–4 | 约 1–2k |

结论与定档依据：战术局面（吃大子、将死）所有档位均在极低节点数内命中，验证了将死/困毙判定与短程战术在深度边界不漏判（静态搜索兜底）；开局表现随深度显著提升（普通→专家：44k → 1.88M 节点）。据此定档：普通 d3/800ms、困难 d4/2500ms、专家 d5/12000ms；浏览器实测专家档偶发超过预算时会回落至上一完整深度（d4）走法，仍保持合理棋力。入门档为随机合法走法，可立即应招。

## 测试与构建结果

- **单元测试**：`npm test` 通过，共 **35** 例（棋规 17 + AI 搜索 8 + 联机房间 10），覆盖炮隔一子吃子、蹩马腿、自陷将军、解将过滤、将死/困毙、搜索返回合法走法、超时兜底、房间创建/加入/回合校验/版本号/重复消息/仅房主重开等。
- **联机冒烟测试**：`npx vite-node scripts/online-smoke.ts` 共 **15** 项全部通过。
- **类型检查与构建**：`npm run build` 通过（vue-tsc 无错误 + Vite 生产构建成功，Web Worker 独立打包）。
- **浏览器实测（人机）**：执黑翻转、电脑先走、落子动画与最后一步标记对齐、随机重抽签、重开清理、入门档快速应招均通过；AI 模式不连服务端、断网可玩。

## 部署说明

- 前端生产构建产物 `dist/` 为纯静态文件，可部署到任意静态托管（如 Gitee Pages、Nginx）。
- **联机对弈需要 WebSocket 服务端**：静态托管不支持 Node 进程，需在能运行 Node.js 的主机上启动 `npm run server`（或自行反向代理到 8787 端口），并在前端构建时通过 `VITE_WS_URL` 指向服务端地址。仅人机模式时无需服务端。
- 服务端房间保存在内存中，重启即清空，不适合生产级持久化场景（首版范围）。
